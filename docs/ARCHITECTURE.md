# МП Проекты — архитектура

## Этап 0: публичный UI-прототип
- Статический frontend; без серверной авторизации и корпоративных данных.
- Проекты и сотрудники в `src/data.js` вымышлены.
- Демонстрационные действия сохраняются в `localStorage` **только данного браузера**.
- Выбор роли в интерфейсе не предоставляет настоящих прав доступа.
- GitHub Pages используется **исключительно** для публичной демонстрации.

## Целевая архитектура
- Публичная HTTPS-страница входа, защищённая аутентификацией.
- Backend API с проверкой прав для **каждого запроса**, ролями и объектными разрешениями (RBAC + доступ к проектам).
- PostgreSQL для проектов, задач, КТ, KPI, финансов, решений, событий, отчётов.
- Отдельное закрытое хранилище вложений и журнал всех изменений.
- Argon2id для паролей; HttpOnly + Secure + SameSite cookie; CSRF, rate limiting, MFA администраторов, резервные копии.
- Уведомления внутри портала и по согласованному почтовому серверу.
- Интеграции с Directum/1С/SSO в последующих версиях после согласования.

## Пилот
Портфель СЦ-2. Проектная модель универсальна, но не выводит другие цели в демонстрационных реестрах.
РП обновляет проект ежемесячно; контрольные точки отслеживаются независимо от ежемесячного отчёта.
Приёмка контрольных точек в пилоте — руководителем портфеля.
Центральный проектный офис — наблюдатель.
Ректор — обзор агрегированных показателей и раскрытие проекта по клику.

## Границы безопасности
Никаких настоящих имён, внутренних документов, бюджетов, токенов, учётных данных и проектных паспортов в публичном GitHub. Проверка пароля на клиенте (JavaScript) **не обеспечивает безопасность**. Серверный контур необходимо подготовить отдельно перед подключением реальных данных.

## Использование готовых систем
ProjeQtOr — референс функций проектного офиса; Plane — референс удобства интерфейса.
Пока в репозитории **нет исходников ProjeQtOr или Plane**: прототип написан отдельно.
Перед заимствованием стороннего кода проверить лицензирование, AGPLv3 и модель развёртывания.
