# МП Проекты · интерактивный прототип v0.1

Прототип портала управления портфелем образовательных проектов (пилот **СЦ-2**). Архитектура будущей системы рассчитана на расширение на другие портфели. Функциональная концепция: портфельный контроль ProjeQtOr + простой современный интерфейс в духе Plane + собственная методология Московского Политеха.

> **ВНИМАНИЕ: это прототип, не рабочая система!** Все данные в `src/data.js` **полностью вымышлены**. Авторизации, серверного разграничения прав, защищённого хранения данных, email-рассылки и официального согласования пока **нет**. Переключатель ролей в верхней части — только демонстрация UI. Все изменения сохраняются в `localStorage` браузера и не синхронизируются между пользователями. Никогда не загружайте сюда настоящие конфиденциальные паспорта проектов.

## Как посмотреть локально

На компьютере с Python 3:

```bash
cd project_office
python -m http.server 8000
```

Открыть http://localhost:8000/ . Можно также использовать VS Code Live Server.

Проект не использует CDN, npm-пакеты, аналитику, сторонние шрифты или внешние сетевые запросы. Веб-сервер нужен для ES-модулей (`type=module`).

## Работает в прототипе

- Обзор портфеля со статусами проектов 🟢 / 🟡 / 🔴 и причинами отклонений;
- реестр проектов с поиском и фильтрами, создание карточки;
- task tracker Kanban с перетаскиванием карточек, сменой статуса и созданием задач;
- контрольные точки КТ-0/1/2, фиксация подтверждения, отправка на приёмку, принятие и возврат;
- календарь контрольных точек;
- список проектных инициатив и демонстрация маршрута согласования;
- автоматический сводный отчёт, экспорт CSV, печать / сохранение PDF средствами браузера;
- форма ежемесячного отчёта РП;
- карточка проекта (вкладки, KPI, финансы, обсуждения), лента событий;
- демонстрационный переключатель роли пользователя.

## Что НЕ реализовано (требуется backend)

- Надёжный вход по паролю, восстановление доступа, сессии, RBAC, аудит;
- единая защищённая БД и файловое хранилище;
- настоящие согласования и маршрутизация по ролям;
- реальные вложения и адресные @упоминания;
- email и внутренние уведомления в реальном времени;
- интеграции с 1С / Directum / справочниками сотрудников;
- официальная выгрузка DOCX/PPTX и межпроектная аналитика KPI.

## Публикация демонстрации через GitHub Pages

1. Создайте **отдельный** репозиторий (рекомендуемое имя `project_office`). Для статической демоверсии без конфиденциальных данных допустим публичный репозиторий.
2. Поместите содержимое этой папки в корень репозитория.
3. В GitHub Settings → Pages выберите **GitHub Actions** как источник публикации.
4. Workflow `.github/workflows/deploy.yml` опубликует статические файлы.
5. Адрес страницы обычно: `https://mp-digital-tools-IP.github.io/project_office/`.

**GitHub Pages НЕ защищает частные данные логином и паролем.** Не размещайте в репозитории настоящие паспорта, бюджеты, персональные данные, пароли или токены. Для рабочего режима приложение подключается к отдельному серверному API с аутентификацией.

## Структура

- `index.html` — точка входа;
- `src/styles.css` — UI, адаптивная компоновка и печатный стиль;
- `src/data.js` — синтетические демонстрационные проекты;
- `src/app.js` — компоненты интерфейса и интерактивная логика;
- `docs/ARCHITECTURE.md` — целевая архитектура и границы безопасности;
- `docs/DATA_MODEL.md` — сущности, роли, пороги, жизненный цикл;
- `.github/workflows/deploy.yml` — автоматическое размещение демонстрации.
